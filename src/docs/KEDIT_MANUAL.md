# KEDIT 1.15 사용 설명서

이 설명서는 **KEDIT 1.15**의 설명서입니다. 편집기를 켜면 맨 아랫줄 처음 메시지에 같은 판 번호(`KEDIT 1.15`)가 나옵니다. 판이 다르면 설명이 다를 수 있습니다.

KEDIT는 애플 II 플러스에서 한글과 영문을 함께 쓰는 전체 화면 글 편집기입니다.
K-HANGEUL 한글 드라이버 위에서 돌아가며, 전부 6502 어셈블리로 만들었습니다. BASIC이나 K-BASIC은 필요 없습니다.

키는 바꿀 수 있습니다: 시작할 때 디스크의 `KEYS` 파일을 읽고, Applesoft 프로그램 `KEYCFG`로 `KEYS`를 고칩니다 (12장). 디스크에 들어 있는 `KEYS`는 5장의 키입니다.

## 1. 필요한 것

| 항목 | 내용 |
|---|---|
| 기종 | 애플 II 플러스, 48K, 랭귀지 카드(16K) 또는 Saturn 128K 카드 |
| 운영체제 | DOS 3.3 |
| 한글 | K-HANGEUL 1.2b |
| 디스크 | `disk\kedit\KEDIT.dsk` (DOS, K-HANGEUL, 글꼴, KEDIT가 들어 있음) |
| 키 설정 | 같은 디스크의 `KEYS`(키 표)와 `KEYCFG`(키를 바꾸는 Applesoft 프로그램). 12장 |

애플 IIe 이상에서도 돌아가게 만들었지만 시험하지는 못했습니다.

## 2. 시작과 끝

- **시작:** `KEDIT.dsk`로 부팅하면 K-HANGEUL을 읽은 다음 바로 편집기가 뜹니다.
  K-HANGEUL이 떠 있는 `]` 프롬프트에서는 `BRUN KEDIT`로 시작합니다. 시작할 때마다 `KEYS` 파일을 읽습니다 (12장).
- **끝:** `ESC`를 누르고 `Q`(또는 `끝`)를 친 다음 `RETURN`. `]` 프롬프트로 돌아갑니다.
- KEDIT는 BASIC 프로그램이 쓰는 메모리를 씁니다. 메모리에 있던 BASIC 프로그램은 없어집니다.

편집기가 뜨면 화면은 비어 있고, 왼쪽 위에 커서가 있으며, 맨 아랫줄에 `KEDIT 1.15  ESC: 명령`이 보입니다. `KEYS` 파일이 없거나 잘못되었으면 대신 `KEYS 파일이 없거나 잘못되어 기본 키를 씁니다`가 나오고 5장의 키를 씁니다.

## 3. 화면

```
0-14줄   글 (한 줄 46칸. 영문 1칸, 한글 한 글자 2칸)
15줄     영 ABC 줄 12/39 칸 7 여유 7312 * DIARY      (반전된 상태 줄)
```

상태 줄에 나오는 것은 왼쪽부터 다음과 같습니다.

| 표시 | 뜻 |
|---|---|
| `한` / `영` | 한글 입력 / 영문 입력 (`Ctrl-A`로 바꿈) |
| `ABC` / `abc` | 영문 대문자 / 소문자 고정 (`Ctrl-Q`로 바꿈) |
| `줄 12/39` | 커서가 있는 줄 / 전체 줄 수 |
| `칸 7` | 커서가 있는 칸 |
| `여유 7312` | 글을 더 쓸 수 있는 바이트 수. 글을 치거나 지울 때마다 바뀝니다. 0이 되면 `메모리가 가득 찼습니다`가 나오고 더 쓸 수 없습니다 (한글 한 글자는 2-5바이트) |
| `*` | 저장한 뒤에 글을 고쳤음 |
| 이름 | 파일 이름. 없으면 `(이름 없음)` |

- 한 줄이 46칸보다 길면 다음 화면 줄로 이어서 보여 줍니다. K-HANGEUL 화면의 46칸을 모두 쓰므로 한글은 한 줄에 23자까지 들어갑니다. 화면 오른쪽 끝의 4화소(글자 한 칸 6화소보다 작음)는 K-HANGEUL이 글을 그리지 못하는 자리입니다. 맨 아랫줄(반전된 줄)은 이 자리도 KEDIT가 칠해서 화면 끝까지 채웁니다.
- 알림(저장했습니다, 찾지 못했습니다 등)도 상태 줄에 나오고, 다음 키를 누르면 사라집니다.
- `ESC`를 누르면 상태 줄이 반전된 채로 `명령:` 뒤에 명령을 치는 명령 줄이 됩니다.

## 4. 글 쓰기

편집기는 모드가 없습니다. 글자를 치면 커서 자리에 바로 들어갑니다.

### 한글

- `Ctrl-A`로 한글 입력과 영문 입력을 바꿉니다.
- 자판은 K-HANGEUL의 두벌식입니다.
- 된소리와 ㅒ, ㅖ는 아래 키로 칩니다.

| 글자 | ㄲ | ㄸ | ㅃ | ㅆ | ㅉ | ㅒ | ㅖ |
|---|---|---|---|---|---|---|---|
| 키 | `-` | `=` | `*` | `<` | `>` | `;` | `+` |

- 한글 입력 상태에서 위 일곱 기호를 글자 그대로 쓰려면 영문 입력으로 바꾸고 칩니다. 숫자와 다른 기호는 한글 입력 상태에서도 그대로 들어갑니다.
- Shift를 쓸 수 있으면 Shift + `R E Q T W`로 된소리를, Shift + `O P`로 ㅒ ㅖ를 칠 수도 있습니다.

### 영문 대문자와 소문자

- `Ctrl-Q`로 대문자 고정(`ABC`)과 소문자 고정(`abc`)을 바꿉니다.
- Shift를 누르고 치면 그 글자만 반대로 들어갑니다.

### Shift

| 기종 | Shift로 쓰는 키 |
|---|---|
| 애플 II 플러스 | Shift 키. 단, 키보드에 "Shift 키 개조"(`$C063` 연결)가 되어 있어야 합니다 |
| 애플 IIe 이상 | 애플 키(열린 사과 또는 닫힌 사과)를 누른 채로 칩니다 (시험하지 못함) |

개조하지 않은 II 플러스와 에뮬레이터의 II 플러스에서는 Shift가 듣지 않습니다. `Ctrl-Q`와 기호 키를 쓰십시오.

## 5. 키

### 커서 옮기기

(키는 `KEYCFG`로 바꿀 수 있습니다: 12장. 아래 표는 디스크에 들어 있는 원래 키입니다. 도움말 `ESC H`에는 지금 쓰는 키가 나옵니다.)

| 키 | 동작 |
|---|---|
| `Ctrl-B`, `←`, `Ctrl-U`, `→` | 한 글자 왼쪽, 오른쪽 (한글은 한 글자씩). 모든 기종에서 같습니다. Shift 키 개조를 한 II 플러스에서는 Shift+`←`가 앞 글자를 지웁니다 (`Ctrl-S`와 같습니다) |
| `Ctrl-K`, `Ctrl-J` | 한 줄 위, 아래 (IIe의 `↑` `↓` 키가 이 코드를 보냅니다). 화면 맨 위나 맨 아래를 넘어가면 화면이 한 줄씩 밀립니다 |
| `Ctrl-O`, `Ctrl-N` | 줄의 처음, 끝 |
| `Ctrl-W`, `Ctrl-Z` | 한 쪽 위, 아래 |
| `Ctrl-T`, `Ctrl-E` | 파일의 처음, 끝 |

### 지우기

| 키 | 동작 |
|---|---|
| `Ctrl-S`, `DELETE` | 커서 앞 글자를 지웁니다. 치고 있던 한글 글자는 자모 하나씩 지우고 (안녕 → 안녀 → 안ㄴ → 안), 이미 끝난 글자는 한 글자를 통째로 지웁니다 (안 → 없음). 커서를 옮기거나 다른 키를 친 뒤에는 모두 통째로 지웁니다. 줄 맨 앞에서는 윗줄과 붙입니다. 모든 기종에서 같습니다. `←`는 지우지 않고 커서를 왼쪽으로 옮깁니다 (PC 키보드의 Backspace는 에뮬레이터에서 `←`로 들어가므로 `Ctrl-S`를 쓰십시오) |
| `Ctrl-D` | 커서 자리의 글자를 지웁니다. 줄 끝에서는 아랫줄을 붙입니다 |
| `Ctrl-X` | 커서부터 줄 끝까지 지웁니다 |
| `Ctrl-Y` | 줄 전체를 지웁니다. 지운 줄은 기억해 둡니다 |
| `Ctrl-G` | 커서가 있는 줄을 복사해 기억해 둡니다 (줄은 그대로). `Ctrl-P`로 넣습니다 |
| `Ctrl-C` | 문단 지움: 커서 줄부터 다음 빈 줄 앞까지 지웁니다. 지운 마지막 줄은 기억해 둡니다 (`Ctrl-P`) |

### 되돌리기

| 키 | 동작 |
|---|---|
| `Ctrl-R` | 커서가 있는 줄을 고치기 전 모습으로 되돌립니다. 한 번 더 누르면 고친 모습이 다시 나옵니다 |
| `Ctrl-P` | 기억해 둔 줄(`Ctrl-Y`로 지운 줄이나 `Ctrl-G`로 복사한 줄)을 커서 줄 위에 넣습니다. 여러 번 넣을 수 있습니다 |

### 그 밖의 키

| 키 | 동작 |
|---|---|
| `RETURN` | 줄을 나눕니다 (새 줄) |
| `Ctrl-A` | 한글 / 영문 |
| `Ctrl-Q` | 대문자 / 소문자 |
| `Ctrl-F` | 같은 낱말을 다시 찾습니다 |
| `Ctrl-L` | 화면을 다시 그립니다 |
| `Ctrl-I` (Tab) | 빈칸 하나를 넣습니다 |
| `ESC` | 명령 줄을 엽니다 |

화면을 그리는 동안에도 키를 미리 칠 수 있습니다. 쪽 넘김 키를 여러 번 이어 누르면 화면은 마지막에 한 번만 그립니다.

## 6. 명령

`ESC`를 누르면 맨 아랫줄에 `명령:`이 나옵니다. 그 뒤에 명령을 치고 `RETURN`을 누르면 실행합니다. `ESC`를 한 번 더 누르면 그만둡니다.
명령 줄에서도 `Ctrl-A`로 한글과 영문을 바꾸고, `Ctrl-S`나 `←`로 지웁니다.
명령은 한글 이름과 영문 이름 어느 쪽으로 쳐도 됩니다. 영문은 대소문자를 가리지 않습니다.

### 파일

| 한글 | 영문 | 동작 |
|---|---|---|
| `저장 [이름]` | `W [이름]`, `SAVE` | 저장합니다. 이름을 주면 그 이름으로 저장하고, 그 뒤로는 그 이름이 파일 이름이 됩니다 |
| `열기 이름` | `E 이름`, `OPEN` | 파일을 엽니다. 없는 이름이면 새 파일로 시작합니다. 고친 글이 있으면 `저장할까요? Y:저장 N:버림 다른 키:취소`라고 묻습니다 (`새로`와 같습니다). `E!`는 묻지 않고 버리고 엽니다 |
| `넣기 이름` | `R 이름` | 다른 파일을 커서 자리에 끼워 넣습니다 |
| `새로` | `N`, `NEW` | 이름 없는 빈 글로 시작합니다. 저장한 글이면 바로 시작합니다. 고친 글이 있으면 `저장할까요? Y:저장 N:버림 다른 키:취소`라고 묻습니다. `Y`는 저장한 뒤 새 글을 시작하고 (이름이 없으면 `파일 이름이 필요합니다`가 나오고 그대로 남습니다. `저장 이름`으로 먼저 저장하십시오), `N`은 고친 것을 버리고 시작하고, 다른 키는 취소합니다. `N!`, `새!`는 묻지 않고 버립니다 |
| `목록 [디스크]` | `LS [디스크]`, `CAT`, `DIR`, `LIST` | 디스크의 파일 목록. 디스크를 `S6,D2`처럼 쓰면 그 디스크의 목록이고, 그 디스크가 이때부터 쓰는 디스크가 됩니다 (DOS와 같습니다). (목록은 잠금 표시 `*`, 종류, 섹터 수, 이름). 한 쪽이 차거나 목록이 끝나면 멈추고, `Ctrl-K` `Ctrl-J`로 줄을 고르면 그 줄이 반전됩니다. `RETURN`은 고른 파일을 엽니다 (고친 글이 있으면 위와 같이 묻습니다. 텍스트 파일이 아니면 열지 않습니다). `ESC`는 글로 돌아갑니다. 다른 키는 다음 쪽을 보여 주고, 마지막 쪽에서는 글로 돌아갑니다 |
| `디스크 S6,D2` | `CHD S6,D2` | 파일(`열기`, `넣기`, `저장`, `목록`)을 읽고 쓸 디스크를 바꿉니다. DOS 3.3 방식으로 `S6,D2`(슬롯 6, 드라이브 2), `D2`(드라이브 2), `S5`(슬롯 5)라고 씁니다. `2`, `62`도 됩니다 (숫자 하나는 드라이브, 둘은 슬롯과 드라이브). 바꾸면 `디스크 [S6,D2]`라고 알려 줍니다. 시작할 때는 DOS의 기본 디스크입니다 |
| `끝` | `Q`, `QUIT` | 편집기를 끝냅니다. 고친 글이 있으면 거절합니다 |
| `끝!` | `Q!` | 저장하지 않고 끝냅니다 |
| `저장끝` | `WQ`, `X` | 저장하고 끝냅니다 |

파일 이름은 한글(`열기 일기`)도 영문도 됩니다.

### 찾기와 이동

| 한글 | 영문 | 동작 |
|---|---|---|
| `찾기 낱말` | `F 낱말`, `FIND`, `/낱말` | 커서 다음부터 낱말을 찾습니다. 파일 끝까지 없으면 처음부터 이어서 찾습니다. `Ctrl-F`로 다음 것을 찾습니다 |
| `줄 N` | `G N`, 또는 숫자만 | N번째 줄로 갑니다 |
| `번호` | `NU` | 줄 번호를 보이거나 숨깁니다 |

- 영문은 대소문자를 가리지 않고 찾습니다.
- 한글은 친 키대로 찾습니다. 그래서 `하`를 찾으면 `한`에서도 멈춥니다.

### 지우기

| 한글 | 영문 | 동작 |
|---|---|---|
| `다지움!` | `DA!` | 글 전체를 지웁니다. 디스크의 파일은 저장하기 전까지 그대로입니다 |

### 알아보기

| 한글 | 영문 | 동작 |
|---|---|---|
| `정보` | `I` | 글의 크기와 남은 메모리를 바이트로 보여 줍니다 |
| `도움` | `H`, `HELP`, `?` | 키와 명령 목록을 보여 줍니다 |

## 7. 되돌리기의 한계

KEDIT에는 일반적인 "실행 취소"가 없습니다. 되돌릴 수 있는 것은 두 가지뿐입니다.

- **한 줄 안에서 고친 것:** `Ctrl-R`. 커서가 그 줄에 있는 동안만 됩니다.
- **지운 줄:** `Ctrl-P`. 마지막으로 지우거나 복사한 한 줄만 기억합니다.

다음은 되돌릴 수 없습니다.

- 줄을 붙이거나 나눈 것 (나눈 줄은 `←`로 다시 붙일 수 있습니다).
- `다지움!`으로 지운 글 전체.
- `넣기`로 끼워 넣은 파일.

크게 고치기 전에 먼저 저장하십시오. 잘못되면 `E! 이름`으로 저장해 둔 파일을 다시 엽니다.

## 8. 제한

| 항목 | 한계 |
|---|---|
| 글의 크기 | 7,364바이트. 넘으면 `메모리가 가득 찼습니다`, 큰 파일은 `파일이 너무 큽니다` |
| 한 줄의 길이 | 250바이트. 더 긴 줄이 있는 파일은 열지 않습니다 (`너무 긴 줄이 있습니다`) |
| 파일 이름 | 30바이트 (한글 이름은 앞뒤 표시 2바이트 포함) |
| 명령 줄 | 60바이트 |
| 파일 종류 | DOS 텍스트 파일(T)만. 다른 종류는 `텍스트 파일이 아닙니다` |
| 드라이브 | 지금 쓰고 있는 드라이브만. 명령에서 드라이브를 고를 수 없습니다 |

- 한글 한 글자는 2-5바이트입니다 (한 = 3, 않 = 4). 한글이 이어진 묶음마다 2바이트가 더 듭니다. 한글만 쓰면 대략 2,900-3,500자입니다.
- 저장한 파일은 마지막 줄 끝에 항상 Return이 붙습니다.
- 저장은 먼저 `KEDIT.TMP`라는 임시 파일에 글을 다 쓴 다음, 옛 파일을 지우고 임시 파일의 이름을 바꿉니다. 그래서 쓰는 도중에 디스크 오류가 나도 옛 파일은 그대로 남습니다. 글은 메모리에도 남아 있으니 다른 디스크에 다시 저장할 수 있습니다.
- 디스크에 옛 파일과 새 파일이 함께 들어갈 자리가 없으면(`디스크가 가득 찼습니다`가 날 경우) 1.2처럼 옛 파일을 먼저 지우고 그 자리에 씁니다. 이때는 쓰는 도중 오류가 나면 옛 파일이 없습니다.
- 잠긴 파일에 저장하려 하면 `파일이 잠겨 있습니다`가 나오고 옛 파일은 그대로입니다. 다른 이름으로 저장하십시오.
- `KEDIT.TMP`는 KEDIT가 쓰는 이름입니다. 이 이름의 파일은 저장할 때 지워지므로 글 파일 이름으로 쓰지 마십시오.
- 만들지 않은 기능: 바꾸기, 거꾸로 찾기, Saturn 카드를 쓴 큰 파일.
- 시험하지 못한 것: 애플 IIe 이상에서의 동작 전체, 특히 애플 키를 Shift로 쓰는 것 (시험에 쓰는 MAME에 IIe ROM이 없습니다). 실제 기계에서의 동작. 저장 도중의 입출력 오류(디스크 불량)는 에뮬레이터에서 만들 수 없어 시험하지 못했습니다.
- `Ctrl-J`(아래)와 `Ctrl-K`(위)는 MAME 키보드로는 넣을 수 없어 (`Ctrl-J`가 Return으로 들어감) 키 코드를 직접 넣는 방법으로 시험했습니다.

## 9. 파일 형식

KEDIT가 만드는 파일은 K-HANGEUL의 글 형식(N-바이트)입니다. KS 완성형, 조합형, 유니코드가 아니라 **두벌식으로 친 키를 그대로** 담습니다.

| 내용 | 바이트 |
|---|---|
| 한글 묶음의 시작 | `Ctrl-K` (`$8B`) |
| 자모 키 | 두벌식 자판의 대문자, 비트 7을 켬 (ㄱ = `R` = `$D2`, ㅏ = `K` = `$CB`) |
| 한글 묶음의 끝 | `Ctrl-A` (`$81`) |
| 영문, 숫자, 기호 | ASCII, 비트 7을 켬 (빈칸 = `$A0`) |
| 줄 끝 | Return (`$8D`) |

예: `한글 123` → `8B C7 CB D3 D2 CD C6 81 A0 B1 B2 B3`

- K-HANGEUL 화면에 그대로 찍을 수 있고, K-BASIC과 kScheme의 소스 파일도 같은 형식입니다.
### PC에서 파일 바꾸기: `nbyte.py`

`disk` 폴더의 `nbyte.py`는 KEDIT 파일(N-바이트)과 PC의 UTF-8 글 파일을 서로 바꾸는 파이썬 프로그램입니다.
K-HANGEUL 프로젝트의 것을 그대로 옮겨 놓았습니다. 파이썬 3만 있으면 되고 다른 꾸러미는 필요 없습니다.

| 명령 | 하는 일 |
|---|---|
| `python nbyte.py decode 입력 출력` | KEDIT 파일 → UTF-8 글 파일 (줄 끝은 LF) |
| `python nbyte.py encode 입력 출력` | UTF-8 글 파일 → KEDIT 파일 |
| `python nbyte.py check 입력` | KEDIT 파일을 풀었다가 다시 만들어 원래와 같은지 확인 |

디스크 이미지에서 파일을 꺼내고 넣는 데는 AppleCommander(`acx`)를 씁니다. `disk` 폴더에서 다음과 같이 합니다.

**애플 → PC** (디스크의 `DIARY`를 PC에서 읽기)

```
acx -g KEDIT.dsk DIARY diary.nb
python nbyte.py decode diary.nb diary.txt
```

**PC → 애플** (PC에서 쓴 `memo.txt`를 디스크에 `MEMO`로 넣기)

```
python nbyte.py encode memo.txt memo.nb
acx -p KEDIT.dsk MEMO TXT 0 < memo.nb
```

- `TXT`는 대문자로 씁니다. 소문자로 쓰면 `acx`가 이진 파일(B)로 넣어서 KEDIT가 열지 못합니다.
- PC의 글 파일은 UTF-8로 저장합니다. 한글, 영문, 숫자, ASCII 기호만 쓸 수 있습니다. 한자나 그림 글자가 있으면 `encode`가 오류를 냅니다. 가운뎃점 ㆍ(U+318D)도 마찬가지이므로 마침표 `.`로 바꿔 쓰십시오.
- KEDIT의 한계는 그대로입니다. 바꾼 파일이 7,364바이트를 넘거나 한 줄이 250바이트를 넘으면 열리지 않습니다.
- `acx`는 이름에 제어 문자를 받지 못해서 한글 이름 파일은 꺼내거나 넣지 못합니다. 영문 이름으로 넣은 뒤 KEDIT에서 `저장 한글이름`으로 다시 저장하고, 꺼낼 때는 반대로 영문 이름으로 저장한 뒤 꺼내십시오.
- 에뮬레이터가 디스크 이미지를 열고 있는 동안에는 `acx`로 넣거나 꺼내지 마십시오.

## 10. 알림 말

| 알림 | 뜻 |
|---|---|
| `저장했습니다` / `읽었습니다` / `넣었습니다` | 저장, 열기, 넣기가 끝났습니다 |

| `저장하지 않았습니다 (끝! 이나 Q! 로 나가기)` | 고친 글이 있습니다. 저장하거나 `!`를 붙이십시오 |

| `찾지 못했습니다` | 찾는 낱말이 없습니다 |

| `메모리가 가득 찼습니다` | 글이 더 들어갈 자리가 없습니다 |
| `파일이 너무 큽니다` / `너무 긴 줄이 있습니다` / `텍스트 파일이 아닙니다` | 열 수 없는 파일입니다 (8장) |

| `쓰기 금지된 디스크입니다` / `디스크가 가득 찼습니다` / `파일이 잠겨 있습니다` / `입출력 오류` / `디스크 오류 N` | DOS의 디스크 오류입니다 |

삑 소리는 그 자리에서 할 수 없는 일을 뜻합니다 (파일 맨 앞에서 지우기, 되돌릴 것이 없을 때 `Ctrl-R`, 줄이 250바이트를 넘게 될 때 등).

## 12. 키 바꾸기 (KEYS 파일과 KEYCFG)

1.7부터 편집기는 하나(`KEDIT`)이고 디스크도 하나(`disk\kedit\KEDIT.dsk`)입니다. `KEDIT`는 시작할 때마다 디스크의 **`KEYS` 파일**에서 키 표를 읽습니다. 키를 바꾸려면 Applesoft 프로그램 **`KEYCFG`**로 `KEYS`를 고칩니다. 디스크에 들어 있는 `KEYS`는 5장의 키(원래 키)이므로, 아무것도 하지 않으면 전과 똑같이 씁니다.

| 파일 | 하는 일 |
|---|---|
| `KEDIT` | 편집기. `BRUN KEDIT`(또는 부팅)할 때마다 `KEYS`를 읽습니다 |
| `KEYS` | 키 표 (32바이트, DOS 바이너리 파일) |
| `KEYCFG` | 키 표를 고치는 Applesoft 프로그램 (한글 화면) |
| `KSTART` | 부팅 때 `BRUN K-HANGEUL`, `BRUN KEDIT`를 실행하는 EXEC 파일 |

### 12.1 시작할 때 `KEYS`를 읽는 방법

- `KEDIT`가 뜰 때 현재 드라이브에서 `KEYS`를 읽어 키 표로 씁니다. `BRUN KEDIT`로 시작해도, 부팅으로 시작해도 같습니다.
- **`KEYS`가 없거나 쓸 수 없으면** (크기가 32바이트가 아니거나, 키 표에 31보다 큰 번호가 있는 경우) 맨 아랫줄에 `KEYS 파일이 없거나 잘못되어 기본 키를 씁니다`가 나오고 **원래 키**(5장)로 시작합니다. 편집은 그대로 할 수 있습니다.
- 도움말(`ESC H`)에는 **지금 쓰는 키**가 나옵니다. 키를 바꾸면 도움말도 바뀝니다. 키가 하나도 없는 명령은 `^-`로 보입니다.
- 키 표를 읽는 코드가 들어가서 1.7의 글의 크기 한계는 6,718바이트였습니다 (1.6은 6,983바이트). 1.10에서 프로그램을 줄여 7,765바이트가 되었습니다.

### 12.2 KEYCFG: 키 바꾸기

1. 편집기를 끝냅니다 (`ESC`, `Q`, `RETURN`). `]` 프롬프트가 나옵니다.
2. `RUN KEYCFG` 를 치고 RETURN. (K-HANGEUL이 올라 있는 디스크에서 하십시오. `KEDIT.dsk`로 부팅한 뒤 편집기를 끝내면 됩니다.)
3. 명령 22개가 두 줄(왼쪽 11개, 오른쪽 11개)로 한꺼번에 나오고, 명령마다 지금 붙은 키가 보입니다. 화면은 이렇게 보입니다 (한글 화면입니다).

```
KEDIT 키 설정  (반전 = 키를 잃음)
>왼쪽           ^B      글자 지움      ^D
 오른쪽         ^U      줄 끝까지 지움 ^X
 위 줄          ^K      줄 지움        ^Y
 아래 줄        ^J      줄 붙임        ^P
 줄 처음        ^O      줄 복사        ^G
 줄 끝          ^N      줄 되돌림      ^R
 앞 쪽          ^W      다시 찾기      ^F
 다음 쪽        ^Z      대소문자       ^Q
 글 처음        ^T      탭             ^I
 글 끝          ^E      다시 그림      ^L
 앞 글자 지움   ^S      문단 지움      ^C

컨트롤 키 = 이 동작에 붙임  ^U 다음  ^H 앞
C 지움 R 처음으로 S 저장 Q 끝 I ^I 붙임
고정: ^A ^H ^M ESC
```

4. `>`가 붙은 명령이 지금 고치는 명령입니다. 다른 명령으로 옮기려면 오른쪽 화살표 (`Ctrl-U`, 또는 `N`, 스페이스)를 누르고, 앞으로 가려면 왼쪽 화살표 (`Ctrl-H`, 또는 `P`)를 누릅니다. 목록 끝에서는 한 바퀴 돕니다.
5. 지금 명령에 붙일 키를 **컨트롤 키로** 누릅니다 (`Ctrl`을 누른 채 글쇠). 그 키가 목록에 바로 나타나고 아랫줄에 `^N 로 정함`처럼 나옵니다. **그 키가 다른 명령에 붙어 있었으면** 그 명령은 키를 잃고, 아랫줄에 `(줄 끝 키 뺏음)`처럼 이름이 나오며 그 명령이 **반전**으로 보입니다 (다음 키를 칠 때까지). 키가 하나도 없는 명령도 계속 반전으로 보이고 키 자리에 `-`가 나옵니다. 같은 명령에 키를 더 붙여도 됩니다 (목록에는 3개까지 보입니다).
6. Apple IIe 의 `Tab` 키는 `Ctrl-I`를 보냅니다. `Ctrl-I`는 다른 컨트롤 키와 같이 누르면 지금 명령에 붙습니다. Tab 키가 없는 Apple II+ 에서는 글자 `I`를 눌러도 `Ctrl-I`가 붙습니다. 화살표 키는 명령을 옮기는 데 쓰므로 `Ctrl-U`(오른쪽)와 `Ctrl-H`(왼쪽, 원래 바꿀 수 없는 키)는 명령에 붙일 수 없습니다.
7. 다 끝나면 `S`. 키가 하나도 없는 명령이 있으면 `키 없는 동작 있음. 저장할까요 (Y/N)?` 하고 묻습니다. `Y`면 저장하고, 다른 키면 돌아갑니다.
8. `저장했습니다. KEDIT 를 시작하면 이 키를 씁니다.` 가 나오면 끝입니다. `BRUN KEDIT`로 편집기를 다시 시작하면 새 키를 씁니다.

| 누르는 키 | 하는 일 |
|---|---|
| 컨트롤 키 (`Ctrl-A`...) | 그 키를 지금 명령에 붙입니다 |
| `I` | `Ctrl-I`를 지금 명령에 붙입니다 |
| `Ctrl-U` (오른쪽 화살표), `N`, 스페이스 / `Ctrl-H` (왼쪽 화살표), `P` | 다음 / 앞 명령 (끝에서 한 바퀴 돕니다) |
| `C` | 지금 명령에 붙은 키를 모두 뗍니다 (그 키들은 삑 소리만 납니다) |
| `R` | 모두 처음으로: `1` 원래 키 (5장), `2` IJKL 견본. 다른 키는 취소 |
| `S` | 저장하고 끝냅니다 |
| `Q` | 저장하지 않고 끝냅니다 |

**명령 22개:** 커서 왼쪽·오른쪽·위·아래, 줄 처음·끝, 쪽 위·아래, 파일 처음·끝, 앞 글자 지움, 글자 지움, 줄 끝까지 지움, 줄 지움, 문단 지움, 줄 넣기(붙임), 줄 복사, 줄 되돌리기, 다시 찾기, 대문자/소문자, 탭, 화면 다시 그림.

**바꿀 수 없는 것**
- 키: `Ctrl-A`(한글/영문), `Ctrl-H`(`←`), `Ctrl-M`(RETURN), `ESC`. 누르면 `^A 는 고정 키`처럼 나옵니다. 이 네 키는 항상 원래 일을 합니다.
- 글자 키 (`A`, `1`, `,` ...): 컨트롤 키만 붙일 수 있습니다.
- `ESC` 명령 줄에서 쓰는 키(`←`, `Ctrl-S`, `Ctrl-X`, `DELETE`, RETURN, `Ctrl-A`)와 명령 이름(`저장`, `W` 등)은 그대로입니다.
- `목록`(`LS`)에서 파일을 고르는 키는 위·아래로 붙인 키를 따릅니다. 안내 줄에는 `위/아래 고르기`로 나옵니다.
- 새 명령을 만들거나 키 하나에 여러 동작을 묶을 수는 없습니다.

**알아 둘 것**
- `KEYCFG`는 키를 치는 동안 K-HANGEUL이 받아 둔 키도 읽으므로 빠르게 쳐도 빠지지 않습니다.
- 에뮬레이터에서는 `Ctrl-J`가 Return으로 들어가 쓰기 어려울 수 있습니다. 실제 기계에서는 문제 없습니다.
- 키 표는 `KEYS` 하나뿐입니다. 여러 벌을 쓰려면 `KEYS`를 다른 이름으로 복사해 두었다가 되돌려 놓으십시오 (`RENAME`).

### 12.3 IJKL 견본 키

`KEYCFG`에서 `R`, `2`를 누르면 (그리고 `S`로 저장하면) 이 키가 됩니다.

| 키 | 하는 일 | 원래는 |
|---|---|---|
| `Ctrl-I` | 위로 | 탭 |
| `Ctrl-J` | 왼쪽으로 | 아래로 |
| `Ctrl-K` | 아래로 | 위로 |
| `Ctrl-L` | 오른쪽으로 | 화면 다시 그림 |
| `Ctrl-V` | 탭 | (쓰지 않던 키) |
| `Ctrl-C` | 화면 다시 그림 | 문단 지움 |
| `Ctrl-B` | 아무 일도 안 함 (삑 소리) | 왼쪽으로 |

나머지 키는 5장 그대로입니다. `Ctrl-U`는 오른쪽으로 남겨 두었습니다 (`→` 키가 `Ctrl-U`를 보내기 때문입니다).

**IIe의 화살표 키:** `↑`는 `Ctrl-K`, `↓`는 `Ctrl-J`를 보냅니다. 견본 키에서는 `Ctrl-K`가 아래, `Ctrl-J`가 왼쪽이므로 `↑`는 아래로, `↓`는 왼쪽으로 움직입니다. IIe에서 화살표 키를 쓰려면 `Ctrl-K`를 위로, `Ctrl-J`를 아래로 붙이십시오. (II 플러스의 `←` `→`는 `Ctrl-H`와 `Ctrl-U`를 보내므로 견본 키에서도 그대로 됩니다.)

### 12.4 KEYCFG 프로그램은 이렇게 돌아갑니다

`KEYCFG`는 줄 번호가 붙은 Applesoft 프로그램입니다 (소스 `src\kedit\keycfg.bas`, 디스크에서는 `LIST`로 볼 수 있습니다).

| 줄 | 하는 일 |
|---|---|
| 10-110 | 시작. 명령 22개의 번호와 이름(한글)을 `DATA`에서 읽어 `A()`, `A$()`에 넣습니다 |
| 120-160 | 키 표 `K(0..31)`를 원래 키로 채우고, `KEYS`가 있으면 `BLOAD KEYS,A$300`으로 읽어 옵니다. 읽기에 실패하면(`ONERR`) 원래 키로 시작합니다. 값이 31보다 크면 파일이 이상한 것이므로 버립니다 |
| 200, 1200-1270 | 화면 전체 그리기: 제목, 명령 21개를 두 줄로(1000줄이 한 칸을 그림: `>` 표시, 붙은 키 3개까지, 키를 잃었거나 없으면 반전), 방금 한 일(`M$`), 안내. 화면 위치는 `VTAB` 대신 차례로 찍고 `POKE 36`으로 오른쪽 칸에 맞춥니다 (K-HANGEUL에서는 `VTAB n`이 화면의 n-2째 줄에 나옵니다) |
| 300-395 | 키 하나를 기다려(900줄) 처리: 컨트롤 키면 400줄로, 글자 키면 `N` `P` `C` `R` `S` `Q` `I`. `Ctrl-U`(21)와 `Ctrl-H`(8)는 명령을 옮기고 (`N` `P` 스페이스와 같음), `Ctrl-I`(9)는 다른 컨트롤 키처럼 붙이고, `I`도 `Ctrl-I`를 붙임 |
| 400-430 | 컨트롤 키를 지금 명령에 붙임: `K(키 코드) = 명령 번호`. 바꿀 수 없는 키(1, 8, 13, 27)는 거절. 그 키를 갖고 있던 명령을 찾아 이름을 알리고 `W`에 적어 반전으로 보임 |
| 500-590 | 저장: 키 없는 명령 검사, 확인, 키 표를 `$300`부터 32바이트에 `POKE`, `BSAVE KEYS,A$300,L32` |
| 600-680 | `R` 모두 처음으로 (800줄 원래 키, 820줄 IJKL) |
| 750-760 | 명령에 붙은 키 떼기 (`C`) |
| 900-950 | 키 기다리기. `$C000`(키보드)과 K-HANGEUL이 받아 둔 키(`$942B` 개수, `$942C` 가장 새 것, `$95AE` 키들)를 모두 봅니다 |

화면에 나오는 글은 모두 한글입니다. `PRINT "..."`와 `DATA`의 한글은 K-HANGEUL 프로그램에서처럼 문자열 안에 `Ctrl-K`, 자판 글쇠, `Ctrl-A`로 들어 있습니다. 그래서 `LIST`로 보면 한글 자리가 알아볼 수 없는 영어 글자로 보이지만, `RUN`하면 한글로 나옵니다. 소스 `keycfg.bas`는 UTF-8 한글로 쓰여 있고, `mkdisk.py`가 디스크에 넣을 때 한글 부분을 그 모양으로 바꿉니다. (메시지를 고치려면 `keycfg.bas`의 한글을 고치고 디스크를 다시 만드십시오. 한글 글자 수가 한 줄 46칸 안에 들게 하십시오.)

핵심은 **키 표 `K(키 코드) = 명령 번호`** 입니다. 명령 번호는 원래 그 명령에 붙은 키의 코드입니다 (`Ctrl-B`=2는 왼쪽, `Ctrl-K`=11은 위, ...). 0은 "아무것도 안 함"입니다. 원래 키 표는 `K(J)=J`, IJKL 견본은 `K(9)=11`(`Ctrl-I`가 위), `K(10)=2`(`Ctrl-J`가 왼쪽), `K(11)=10`(`Ctrl-K`가 아래), `K(12)=21`(`Ctrl-L`이 오른쪽), `K(22)=9`(`Ctrl-V`가 탭), `K(3)=12`(`Ctrl-C`가 화면 다시 그림), `K(2)=0`(`Ctrl-B`는 비움)입니다. 820줄에 그대로 쓰여 있으니 견본을 바꾸려면 거기를 고치십시오.

### 12.5 `KEYS` 파일

- DOS 바이너리 파일, 32바이트 (`BSAVE KEYS,A$300,L32`로 만든 것). 키 코드 0-31 각각에 한 바이트: 그 키가 하는 명령 번호 (0-31). 편집기는 앞의 4바이트(주소와 길이)를 보고 길이가 32인지 확인한 다음 32바이트를 읽습니다.
- `KEDIT` 안에는 같은 모양의 표 `keymap`이 있고, 키를 누르면 `명령 번호 = keymap[키 코드]`를 찾아 그 명령을 실행합니다. 시작할 때 `KEYS`를 읽어 이 표를 덮어 씁니다. 읽지 못하면 `keymap`은 `KEDIT` 안에 들어 있는 원래 값(`keymap[J]=J`)입니다.
- 도움말 줄에는 자리 표시(명령 번호)가 들어 있고, `ESC H`를 누를 때 `keymap`에서 그 번호를 가진 가장 앞 키를 찾아 `^X` 모양으로 바꿔 보여 줍니다.
- PC에서 `KEYS`를 만들어 넣을 수도 있습니다: 32바이트 파일을 만들어 `acx -p KEDIT.dsk KEYS bin 0x300 < keys.bin`.

### 12.6 디스크 만들기 (`build_all.bat`)

프로젝트 폴더에서 `build_all.bat`를 실행하면 `disk\kedit\KEDIT.dsk`와 일기장 디스크 `disk\kdiary\KDIARY.DSK`가 만들어집니다 (그 폴더에 매뉴얼과 RELEASE.txt, `nbyte.py`도 복사됩니다) (cc65, 파이썬 3, AppleCommander `acx`가 필요합니다). 같은 일을 직접 하려면 `python src\tools\mkdisk.py`.

- 편집기만 다시 만들 때: `python src\kedit\build.py` (`build\KEDIT.bin`).
- `KEYS`는 디스크를 만들 때마다 원래 키로 새로 씁니다. 디스크에서 `KEYCFG`로 바꾼 키는 디스크를 다시 만들면 없어집니다. 바꾼 키를 보관하려면 `acx -g KEDIT.dsk KEYS keys.bin`으로 꺼내 두십시오.
- AppleWin 같은 에뮬레이터가 디스크 이미지를 열고 있으면 쓸 수 없습니다. 먼저 닫으십시오.

### 12.7 문제가 생기면

| 증상 | 까닭과 해결 |
|---|---|
| 시작할 때 `KEYS 파일이 없거나 잘못되어 기본 키를 씁니다` | 디스크에 `KEYS`가 없거나 이상합니다. 편집은 원래 키로 됩니다. `KEYCFG`를 돌려 `S`로 저장하면 `KEYS`가 새로 생깁니다 |
| 키를 바꿨는데 그대로 | `KEYCFG`에서 `S`로 저장했는지, 그리고 편집기를 다시 시작했는지 보십시오 |
| 어떤 키가 삑 소리만 남 | 그 키가 어떤 명령에도 붙어 있지 않습니다. `KEYCFG`에서 붙이거나 `R`로 되돌리십시오 |
| 위로 갈 키가 없어짐 | `KEYCFG`에서 `R`, `1`로 원래 키로 되돌린 뒤 `S` |
| IIe `↑` `↓`가 엉뚱하게 움직임 | 12.3의 안내대로 `Ctrl-K`=위, `Ctrl-J`=아래로 붙이십시오 |
